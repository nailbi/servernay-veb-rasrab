class NewArticleEvent implements ShouldBroadcast
{
    use Dispatchable, InteractsWithSockets, SerializesModels;

    public function __construct(public Article $article)
    {
    }

    // Публичный канал: уведомление получают все посетители.
    public function broadcastOn(): array
    {
        return [new Channel('test')];
    }

    // Данные, которые уйдут в браузер (ключ article).
    public function broadcastWith(): array
    {
        return [
            'article' => [
                'id'   => $this->article->id,
                'name' => $this->article->name,
            ],
        ];
    }
}

Демонстрация

Как показать работу

Сценарий на 2 минуты

  1. Запустите php artisan serve и php artisan queue:work в двух терминалах.
  2. Окно 1 (обычное): откройте http://localhost:8000/articles и откройте DevTools → Console.
  3. Окно 2 (инкогнито): войдите как moderator@mail.ru, нажмите «Создать новость», заполните и сохраните.
  4. В терминале очереди появятся строки VeryLongJob … DONE и NewArticleEvent … DONE.
  5. В окне 1 справа внизу всплывёт «Добавлена новая статья …», в консоли будет объект {article: {id, name}, socket: null}. Нажмите на название, чтобы перейти к статье.
  6. Для эффекта: на dashboard.pusher.com откройте приложение → Debug console. Там видно подключение браузера и само событие на канале test.

Покажите, зачем нужна очередь

  1. Остановите queue:work (Ctrl+C) и создайте ещё одну статью: уведомления нет, задание лежит в таблице jobs.
  2. Снова запустите queue:work: задание выполнится, и уведомление сразу всплывёт.

Если что-то не работает

Ошибки, которые уже встречались

Все они случились при настройке этой лабы. Если спросят «какие были трудности», это готовый ответ.

cURL error 60: unable to get local issuer certificate

PHP на Windows не знает корневые SSL-сертификаты. В .env указан PUSHER_CA_BUNDLE (bundle из Git for Windows), он передаётся Guzzle как verify. Другой способ: curl.cainfo в php.ini.

Pusher error: Invalid signature

Неверный PUSHER_APP_SECRET. Сервер подписывает запрос HMAC-SHA256 секретом, Pusher проверяет подпись. Секрет — 20 символов 0–9 и a–f.

в консоли: state disconnected

Неверный PUSHER_APP_KEY или кластер. Ключ встроен в JS при сборке: после правки .env нужен npm run build.

уведомление не приходит, ошибок нет

Не запущен queue:work. Событие лежит в таблице jobs.

Vite: connection refused

Был запущен и закрыт npm run dev, остался файл public/hot. Решение из методички: закрыть dev-сервер и выполнить npm run build.

bootstrap/cache directory must be present and writable

OneDrive ставит на папку атрибут «только чтение». Его сняли, после этого composer смог записать кэш пакетов.

Идея широковещания

Что такое широковещание (broadcasting) в Laravel?›

Это передача серверных событий в браузер в реальном времени. Событие Laravel, помеченное ShouldBroadcast, отправляется в канал, а все браузеры, подписанные на этот канал, сразу получают его по WebSocket. Страницу обновлять не нужно.

Зачем нужен Pusher? Почему Laravel не может отправить данные браузеру сам?›

HTTP работает по схеме «запрос — ответ»: сервер отвечает, только когда браузер спросил. Чтобы сервер мог сам прислать данные, нужно постоянное соединение (WebSocket). php artisan serve и обычный PHP такие соединения не держат. Pusher — внешний сервис, который держит WebSocket-соединения со всеми браузерами. Laravel отправляет ему событие одним HTTP-запросом, а Pusher рассылает его подписчикам.

Альтернативы: Laravel Reverb (свой WebSocket-сервер, в Laravel 11+ это вариант по умолчанию), Ably, Soketi.

Почему уведомление получают только те, кто сейчас на сайте?›

Событие нигде не сохраняется для браузеров. Pusher отправляет его тем, кто в этот момент подключён к каналу test. Кто зайдёт позже, его не увидит. Именно это и требовалось в задании: оповестить тех, кто сейчас на сайте.

Чем это отличается от письма модератору из ЛР8 и ЛР10?›

Письмо адресное и сохраняется: его получат только модераторы, и прочитать можно когда угодно. Пуш через широковещание получают все посетители, но только в момент, когда страница открыта. Оба запускаются из ArticleController@store и оба идут через очередь.

Событие на сервере

Что делает интерфейс ShouldBroadcast? Чем он отличается от ShouldBroadcastNow?›

По этому интерфейсу Laravel понимает, что событие нужно транслировать. При dispatch он кладёт в очередь задание BroadcastEvent, а воркер уже отправляет его в Pusher. С ShouldBroadcastNow отправка идёт сразу, в том же запросе, без очереди. Тогда пользователь ждёт ответа Pusher, а при ошибке Pusher сломается и сохранение статьи.

Почему Channel, а не PrivateChannel? Какие ещё бывают каналы?›
  • Channel — публичный, подписаться может кто угодно без авторизации. Подходит, потому что уведомление для всех посетителей.
  • PrivateChannel — перед подпиской браузер спрашивает Laravel (/broadcasting/auth), разрешено ли. Правила пишутся в routes/channels.php. Подходит для личных уведомлений.
  • PresenceChannel — приватный канал, который ещё и знает, кто в нём сейчас (например, «кто онлайн»).
Что возвращают broadcastOn и broadcastWith?›

broadcastOn — список каналов, в которые уйдёт событие (у нас один: test). broadcastWith — массив данных, которые получит браузер. Если его не написать, Laravel отправит все публичные свойства события, то есть модель статьи целиком, включая полный текст. Это лишний трафик, а у Pusher ограничение 10 КБ на событие.

Почему на клиенте пишется listen('NewArticleEvent') без пространства имён?›

По умолчанию событие транслируется под полным именем класса App\Events\NewArticleEvent. Echo сам дописывает пространство имён App\Events к имени из listen. Если в событии задать broadcastAs() со своим именем, на клиенте нужно писать его с точкой в начале: .listen('.article.created', …).

Зачем в событии SerializesModels?›

Событие сохраняется в таблицу jobs. SerializesModels записывает туда не всю статью, а только её id. Перед отправкой воркер заново загружает статью из базы, поэтому данные свежие. Так же было с VeryLongJob в ЛР10.

Зачем запускать queue:work? Что будет без него?›

ShouldBroadcast отправляет событие через очередь, а очередь у нас в базе (QUEUE_CONNECTION=database). Без воркера задание просто лежит в таблице jobs, и уведомление никто не получит. Когда воркер запустится, он выполнит накопившиеся задания.

Автор статьи тоже видит уведомление. Как его исключить?›

Вызвать broadcast(new NewArticleEvent($article))->toOthers() и добавить в событие трейт InteractsWithSockets (он уже есть). Echo добавляет к axios-запросам заголовок X-Socket-ID с id соединения, и Pusher не отправит событие этому соединению. Работает, только если форма отправлена через axios. У нас обычная HTML-форма, поэтому автор после перехода на новую страницу тоже может увидеть уведомление.

Клиент: Echo, Vue, Vite

Что такое Laravel Echo и pusher-js? Почему нужны оба?›

pusher-js — официальный клиент Pusher: открывает WebSocket и подписывается на каналы. laravel-echo — обёртка от Laravel поверх него: удобные методы channel, private, listen, автоматическое имя события и авторизация приватных каналов. Echo использует Pusher из window.Pusher.

Почему ключ Pusher лежит в JS, а секрет нет? Что значит префикс VITE_?›

Ключ (key) публичный: он только говорит Pusher, к какому приложению подключаться, и может быть виден в браузере. Секрет (secret) подписывает запросы на отправку событий. Если он утечёт, кто угодно сможет слать события от имени сайта, поэтому он только на сервере.

Vite передаёт в JS только переменные с префиксом VITE_ (import.meta.env.VITE_PUSHER_APP_KEY). Значение подставляется при сборке, поэтому после смены ключа нужно заново выполнить npm run build.

Как Vue-компонент попадает на страницу?›

В app.js: createApp(App).mount('#app'). Vue находит элемент <div id="app"> в макете и рендерит в нём компонент. Скрипт подключается директивой @vite в <head>. Макет общий для всех страниц, поэтому уведомление приходит на любой странице.

Что делают data(), created(), v-if и :href в App.vue?›
  • data() — реактивное состояние компонента. article: null, пока ничего не пришло.
  • created() — хук жизненного цикла, вызывается при создании компонента. Там подписка на канал.
  • v-if="article != null" — окно есть в DOM, только когда пришли данные. Когда слушатель записал this.article, Vue сам перерисовал шаблон.
  • :href — привязка атрибута к выражению: ссылка собирается из article.id.
Что такое Vite? Чем npm run build отличается от npm run dev?›

Vite собирает JS и CSS: превращает .vue-файлы в обычный JS, объединяет модули из node_modules, подставляет VITE_-переменные. laravel-vite-plugin связывает его с Laravel, а директива @vite подключает нужные файлы.

npm run build один раз собирает файлы в public/build. npm run dev запускает dev-сервер с горячей перезагрузкой: страница берёт скрипты с него, и если его закрыть, будет connection refused. npm run watch пересобирает build при каждом изменении файлов.

Настройка и ошибки

В методичке надо раскомментировать BroadcastServiceProvider. Почему у вас его нет?›

В Laravel 11 и 12 упростили структуру проекта: многих провайдеров и конфигов нет по умолчанию. Конфиг широковещания опубликован командой php artisan config:publish broadcasting. Провайдер в старых версиях только регистрировал маршрут /broadcasting/auth и подключал routes/channels.php. Это нужно для приватных каналов, а у нас публичный.

Что за ошибка cURL error 60 и как вы её решили?›

Laravel отправляет событие в Pusher по HTTPS. Чтобы проверить сертификат сервера Pusher, нужен список корневых сертификатов. PHP, установленный на Windows через winget, этот список не знает. Решение: в client_options Pusher передан verify с путём к CA-bundle (переменная PUSHER_CA_BUNDLE). Проверку сертификата не отключали, это было бы небезопасно.

Что значит Invalid signature от Pusher?›

Каждый запрос на отправку события подписывается HMAC-SHA256 от метода, пути, параметров и тела запроса с секретом приложения. Pusher считает подпись своим экземпляром секрета. Если подписи не совпали, значит, в .env неверный PUSHER_APP_SECRET.

Как проверить, что событие вообще уходит, если уведомления нет?›
  • Терминал queue:work: есть ли строка NewArticleEvent … DONE или FAIL.
  • Pusher → Debug console: видно подключения браузеров и пришедшие события.
  • Консоль браузера: window.Echo.connector.pusher.connection.state должно быть connected.
  • Временно поставить BROADCAST_DRIVER=log: событие запишется в storage/logs/laravel.log вместе с каналом и данными.
